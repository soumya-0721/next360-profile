## Findings

### 1. Cold-load print drops every lazy-loaded photo — HIGH (R-35, C-4)

All content photos use `loading="lazy"`. A PDF generated from a cold load (no prior
scroll) prints them as empty boxes:

- p14 back-strip: cold `rgb(23,56,42)` (sheet background, image absent) vs warm `rgb(140,145,37)` (photo pixel)
- p11 snapshot photo: cold `rgb(173,186,176)` = tint over empty sage placeholder vs warm real photo pixels

The toolbar Print/PDF button path does not force images eager before calling
`window.print()`. If Chrome's print preview does not rescue the lazy images, the
shipped PDF has blank photo slots. This is the primary deliverable, so it is HIGH.

Fix: before printing (button and `beforeprint` for Ctrl+P), set every `img` to
`loading="eager"` and await `img.decode()` with a short timeout, then print.

### 2. "Background graphics" unchecked loses backgrounds the design depends on — HIGH (C-4)

Chrome's print dialog defaults to background graphics OFF. `print-color-adjust:exact`
is only applied to a whitelist (`.sheet-dark, .v-flag, .flag-visual, .cover-bg,
.closing, .photo--tint::before, .cap-row.is-lead`), so everything else drops:

- `.sheet` ivory `rgb(252,251,247)` -> white `rgb(255,255,255)` (sheets 2-5, 8-12)
- `.v-note` sage box -> white (sheet 5)
- `.focus-index li.is-flag` sage highlight row -> white (sheet 12)
- `.v-card`, `.pillar`, `.step .bubble`, figcaption strips lose the subtle
  white-on-ivory separation as well

The user's existing exported PDF has backgrounds (the checkbox was on that time),
so this is a latent defect that fires the next time someone exports with defaults.

Fix: apply `print-color-adjust:exact` inside `@media print` on the whole document
(e.g. on `*` or `body`), not a hand-picked subset.

### 3. Em dash in three visible kickers — HIGH (R-02, Hard Gate)

- line 619: `03 · Core Verticals — IT portfolio, continued`
- line 760: `04 · Flagship Venture — continued`
- line 812: `05 · Technology Ecosystem — continued`

(Line 617 is an HTML comment, exempt as code, but the three renderings are UI text.)

Fix: use the document's existing middle-dot separator:
`04 · Flagship Venture · continued` etc.

### 4. Print button fires window.print() twice — MEDIUM (C-2, R-26)

The button has both an inline `onclick="window.print()"` and an
`addEventListener("click", ...)` in the script. Measured `printCalls: 2` per click.
Depending on Chrome version the second call is swallowed or queues a second dialog.

Fix: keep the JS listener, delete the inline `onclick`.

### 5. og:image (and twitter image fallback) is a relative URL — MEDIUM

`content="assets/cover-hero.jpg"` will not render in any social preview; OG requires
an absolute URL. Relative resolution from `/company-profile` is also ambiguous.

Fix: absolute URL (`https://next360.in/assets/cover-hero.jpg`, confirm the deployed
asset path first).

### 6. meta keywords is ~700 chars of stuffing across unrelated products — MEDIUM

Mixes the organic marketplace with "Slixo billing", "Organize productivity app",
"best organic products Hyderabad", "top organic startup Hyderabad Telangana" etc.
Google ignores meta keywords entirely; in source it reads as spam and dilutes the
page's own topic.

Fix: trim to a short honest set, or drop the tag.

### 7. User-supplied facts render as fact — MEDIUM (R-17, C-5)

"12 Team Members", CIN `U47912TS2026PTC212259`, GSTIN `36AALCN3880H1Z3`,
PAN `AALCN3880H`, phone, T-Hub address. I cannot verify them. Confirm each is
correct before export; a wrong CIN/GSTIN on a printed company profile is costly.

### 8. JSON-LD `subOrganization` contradicts the document's own legal note — MEDIUM (R-38)

Sheet 5 says every vertical is "an operating area ... not a separate legal entity",
while the JSON-LD declares `subOrganization: Slick Technologies` as an Organization.
If Slick Technologies is not a registered separate entity, drop `subOrganization`
and keep it under `brand`.

### 9. "Certificate-based certified organic marketplace" — LOW (R-16 copy redundancy)

og:title/og:description/JSON-LD description stack "certificate-based" on "certified".
Pick one: "certificate-based organic marketplace: verified organic, natural and
eco-friendly products with traceability."

### 10. SEO graphic in card 05 is 105px tall vs 95px photos in the same row — LOW

`.v-art svg` has no height rule; sibling `.v-photo img` is 95px. Bottoms align,
tops differ by 10px. Fix: `.v-art img/svg` height 95px to match.

### 11. Dead CSS and inline styles — LOW (R-31 neatness)

- `.cap-row{padding:17px 8px}` declared twice; the first rule is fully overridden
- `.back-foot` declared twice; the first block is dead
- Two inline `style` attributes on sheet 6/7 headers belong in the stylesheet
