Scope: `src/**`, verified against a running production build.

Evidence base:

- `next build` exit 0, 13 routes

- WCAG contrast probe across all 8 pages (oklab-aware): 0 FAIL after fixes

## Findings

### 1. Placeholder legal name is emitted into JSON-LD structured data — HIGH (R-38)

`src/app/layout.tsx` builds an `Organization` JSON-LD object with
`legalName: company.legalName`, which is the literal string
`[VERIFIED DATA NEEDED: legal/company name]`.

A labelled placeholder is correct in visible UI, but in machine-readable
structured data it is not a disclosure, it is a fabricated-looking value that
search engines and crawlers will read as a real legal entity name.

Fix: omit `legalName` from the JSON-LD object until the client confirms it.

### 2. No `DESIGN.md` at project root — HIGH (R-37)

Design direction exists only in `memory/design-dna.md`. R-37 names `DESIGN.md`
(or explicit brand guidance) as the file the agent loads before building UI.

Direction was followed, but it lives outside the location the rule points at, so
the next session or another agent would build with no direction and could fall
into a sterile default without noticing.

Fix: create `DESIGN.md` at the root holding identity, palette, typography, mood
and the three dials. Reasons currently scattered across code comments and
`memory/design-dna.md` consolidate here (also closes R-31).

### 3. Fixed light theme with no written brand reason — MEDIUM (R-21)

The site ships light only. No toggle, and no one-line reason recorded for why a
fixed theme is correct for Next360.

R-21 requires either a working light/dark toggle or a stated brand/product
reason for a fixed theme. The FRD palette (deep navy, off-white) implies light,
but that implication has not been written down as a theme decision.

Fix: either write the one-line reason in `DESIGN.md`, or build a toggle that
works correctly in both modes (R-34 applies if built).

### 4. Closing CTA band repeats the same composition on 5 pages — MEDIUM (R-05)

`rounded-panel bg-ink px-7 py-14 text-center sm:px-14` appears on
`/`, `/agritech`, `/it-services`, `/capabilities`, `/technology`. Same centered
title, same button row, same dark box.

This is uniform section rhythm across pages: every page resolves to the same
final block, so the composition reads as a template rather than a decision.

Fix: vary the closing composition per page, or extract one shared CTA component
and vary its layout by context. The reason for whichever choice is made must be
written (R-31).

### 5. `.example` domain ships in canonical and Open Graph metadata — MEDIUM (R-38)

`metadataBase: new URL("https://next360.example")` is emitted into canonical
URLs and OG tags on every page.

A reserved TLD is technically an honest placeholder, but unlike the visible
`[VERIFIED DATA NEEDED]` markers it carries no label in the output, so it reads
as a real URL once deployed.

Fix: gate it behind a confirmed domain, or add a visible TODO comment plus a
pre-launch check that fails the build while it is unset.

### 6. The 13-part profile index is rendered twice — LOW (C-3, R-05)

The full profile architecture list appears on `/` (as an ordered row list) and
again on `/about` (as a card grid).

Both are content-driven and not fabricated, but the second copy mostly restates
the first. A section that exists to repeat another section is filler.

Fix: keep the full index on one page and reduce the other to the sections that
page actually needs.

### 7. Projects empty state has no loading or error state — LOW (R-27)

`/projects` ships a labelled empty state (correct, and correctly empty rather
than fabricated), but no loading or error state.

The content is static and prerendered, so neither state can occur today. That
reasoning is not written anywhere, so the gap looks like an omission rather than
a deliberate call.

Fix: write the one-line reason (static prerendered content, R-27 states not
applicable) or add the states if this page later reads from a CMS.

### 8. Vertical cards on the home page are identical but differ only in color — LOW (R-14)

Agritech and IT Services cards share size, padding, layout and structure. The
only variation is tone (green vs navy).

Equal treatment may well be correct here, since the two verticals have equal
standing in the FRD. The problem is that the hierarchy reason is not written, so
the identical cards read as a default rather than a choice.

Fix: write the one-line reason (two verticals of equal standing, differentiated
by scoped accent) in `DESIGN.md`.

### 9. Typeface rationale lives only in a code comment — LOW (R-06)

Source Serif 4, IBM Plex Sans and IBM Plex Mono are chosen for stated reasons,
but the reasons sit in a comment inside `src/app/layout.tsx`.

R-06 requires the reason to be written where direction is held. A code comment
is not the direction file and will not be read before the next build.

Fix: move the three typeface reasons into `DESIGN.md` (closes with finding 2).

## Non-antislop defects found during the audit

These are product/functional issues, not antislop rule violations. Listed
separately so they are not confused with the numbered findings.

A. `robots: { index: false, follow: false }` is set globally in
   `src/app/layout.tsx`. This blocks all indexing on a corporate profile site
   whose stated objective is credibility with prospects, partners and tender
   committees. Likely intended as a pre-launch guard, but there is no comment
   saying so, and it will be missed at launch.

B. Dev artifacts are in the project root: `verify.mjs` and `probe.mjs`.
   `puppeteer-core` was installed with `--no-save` so it is not in
   `package.json`, which is correct, but the two scripts should not ship.

C. The contact endpoint accepts and logs enquiries but does not deliver them
   anywhere. Marked with a TODO and the UI does not claim delivery, so this is
   honest, but it must be wired before launch.

D. The FRD lists DOCX and PDF deliverables. Those are outside the Next.js
   stack and have not been scoped.
