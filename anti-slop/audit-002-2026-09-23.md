## Findings

### 1. Zero vendor-registration identity block — HIGH
As an Indian contractor you have no Saudi CR/MISA/Nitaqat (those are not applicable),
but the profile shows NONE of the identifiers a KSA procurement team verifies on a
foreign vendor: CIN (MCA), GSTIN, PAN, IEC (Import-Export Code), Udyam/MSME,
registered office. Grep: 0 matches for all. Fix: legal-identity block with
`[TO BE CONFIRMED]` slots for the Indian registrations.

### 2. No export/food credentials relevant to KSA — HIGH
The flagship is an organic-products marketplace pitching into Saudi Arabia. KSA imports
require SFDA-recognized certification; Indian side credentials are APEDA registration,
FSSAI license and NPOP/India Organic certification. None appear (grep: 0 matches).
If any are held, they are the single strongest trust signal for this client. Fix:
credentials row, each value `[TO BE CONFIRMED]` — assert nothing.

### 3. English-only is acceptable; Arabic is a trust bonus — MEDIUM (was HIGH)
KSA B2B procurement runs in English, so English-only is NOT a blocker for a contractor
profile. However an Arabic cover strip / bilingual title page measurably raises trust
per KSA profile guidance. Fix (optional): bilingual cover + `dir="rtl"` print variant.

### 4. No Vision 2030 / national-priority alignment — MEDIUM
Agritech ↔ food security and IT ↔ digital transformation align naturally and require no
fabricated claims. For a foreign contractor this is how you speak to KSA priorities
without claiming local presence. Fix: one positioning paragraph in 01/COMPANY or
09/POSITIONING. Do NOT imply a Saudi office or local entity.

### 5. No selected-projects / track-record section — MEDIUM
Saudi profiles are judged on track record (problem → contribution → verified outcome,
per FRD §8). Current 9 sections list verticals but no project evidence. Fix: add a
"Selected Projects" page using only confirmed facts; unknown outcomes = TBC.

### 6. No certifications/registrations section — MEDIUM
Expected slot in any Saudi vendor profile (ISO, MCIT, etc.). Fix: section with TBC
rows; never invent.

### 7. No full contact block — MEDIUM
Closing identity page has no registered-office address, phone, or email. Fix: contact
rows for the Indian registered office + website, all values TBC until supplied.

### 8. Em dashes in profile copy — MEDIUM (R-02)
9 occurrences incl. `<title>`, meta description, cover line, and visible body copy
(lines 1096, 1268). Fix: rewrite with commas/colons.

### 9. Team-size and product-list conflicts across sources — MEDIUM (data integrity)
Profile says 12 members; content-architecture memory says 15. SLICK product lists
differ between the latest prompt and memory. Latest prompt wins, but this must be
explicitly confirmed before client delivery.

### 10. Real-world image pass unfinished — LOW
Previous CC0 image integration (Openverse/Flickr/Commons) was interrupted mid-verify.
Fix: finish URL verification, add lazy-loading + illustrative captions.

### 11. No contract-onboarding document checklist appendix — LOW
A short appendix (documents available on request: CIN, GSTIN, PAN, IEC, Udyam, APEDA,
FSSAI, NPOP, ISO) speeds foreign-vendor onboarding on the KSA side.

### 12. Buzzword scan: PASS — no action
0 matches for seamless/cutting-edge/world-class/next-gen/effortless in profile copy.

### 13. Print/PDF baseline: PASS — no action
A4 @media print verified earlier (page breaks, background preservation, 0 overflow).
